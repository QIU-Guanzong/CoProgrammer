# Evaluation Plan

Last updated: 2026-06-10

## Why

The digest → integration-plan → minimal-patch loop is currently a well-argued
design. To become a credible open protocol (and a publishable result), it needs
numbers. Competing work already publishes triage distributions (AgentSpawn:
auto-merge 15% / semantic merge 73% / escalation 12%). We must show, on real
AI-agent PR conflicts, that protocol-guided semantic integration beats raw
merging.

## Dataset

Primary: **AgenticFlict** (arXiv:2604.03551), a large-scale dataset of merge
conflicts in AI coding agent pull requests on GitHub. Secondary: synthetic
cases generated by `eval/make_synthetic_case.py` (used for harness development
and CI smoke tests), and later our own dogfooding history (integration
records).

Selection rules for the reproducible subset:

- repository must be cloneable at the recorded SHAs;
- conflict must involve ≥ 2 branches or a branch vs. moved main;
- license permits research use;
- target ~100–300 cases stratified by language and conflict size.

## Conditions

| Condition | Description |
| --- | --- |
| `raw_merge` | Plain `git merge` of the agent branch into main at the recorded SHA. Baseline. |
| `structural` | Syntax-aware merge assist where available (e.g. language-aware tools). Optional second baseline. |
| `digest_integration` | CoProgrammer loop: digest the branch, produce an integration plan (preserve/drop/rebuild), rebuild a minimal patch from latest main, validate. |

The `digest_integration` condition is initially **human-in-the-loop** (a team
member approves the plan), matching the product's intended operation. Record
human time spent as a cost metric.

## Metrics

1. **Auto-resolution rate**: share of cases landing without manual conflict
   editing.
2. **Insight recall**: of the branch's core contributions (labelled per case),
   how many survive into the landed patch.
3. **Noise rejection**: share of labelled noise changes (formatting churn,
   unrelated refactors, debug leftovers) correctly excluded.
4. **Regression rate**: share of landed patches failing the repository's own
   test suite or introducing behavioral regressions.
5. **Reviewer load**: number of items requiring a human decision; minutes of
   human time per case.
6. **Patch minimality**: landed diff size vs. original branch diff size.

Alignment check: bucket our cases into the AgentSpawn three-band triage and
report our per-band performance, especially the 73% "semantic merge" band.

## Protocol

1. `eval/make_synthetic_case.py` to develop and smoke-test the harness (no
   network needed).
2. Import AgenticFlict cases into `eval/cases/*.json` (one case per file,
   schema documented in `eval/README.md`).
3. `eval/run_eval.py --condition raw_merge` to produce baseline results.
4. Run `digest_integration` on the same subset.
5. Write `docs/EVAL_REPORT_<date>.md` with metric tables and per-band analysis.

## Output

- `eval/results/*.jsonl` raw per-case records;
- `docs/EVAL_REPORT_<date>.md` summary;
- labelled core-contribution/noise annotations contributed back as an
  extension of the dataset (with attribution, per `ACKNOWLEDGMENTS.md`).
