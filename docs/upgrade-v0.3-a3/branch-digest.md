# Integration digest: local automatic work boundaries

Preserve a2's shared Manager transactions, event replay validation, fenced
claim tokens, explicit reclamation, preview-first setup and provider adapters.
Rebuild only a thin local worker API, CLI/MCP entries, provider routing labels,
installation edition selection and bundled guidance.

- `worker step` previews by default. Applying pulses an active original window,
  stops for pending messages/open decisions, then checks and renews an owned
  claim or atomically claims eligible work. Actual Git changes and planned paths
  are guarded; failures roll back the full transaction.
- Dispatch consumes pending nested transaction events so an applying pulse is
  visible before eligibility selection. Client/provider matching is consistent
  during claim, historical replay and dispatch. Labels remain self-reported.
- `worker finish` checks changes and current ownership, finishes/releases, and
  writes handoffs to explicit local recipients atomically. A deterministic key
  and identical-summary retry check prevent duplicate completion/messages.
- Git change collection ignores caller Git redirection, ensuring the selected
  worktree is inspected. Existing config/certificates/credentials are untouched.
- Skill edition includes six Skills and Markdown, MCP edition includes only
  native config, and default full edition preserves previous file selection.
  Missing-file writes, conflicts, symlink refusal and rollback remain intact.
- GLM/DeepSeek operate through an already configured host. New start metadata
  records provider/model identity; resume cannot silently change that identity.

Drop: model/client launchers, credentials in events, remote queue, event/schema
migration, auto-ACK, automatic takeover, background process liveness, fabricated
connection or user/star claims. No new runtime dependency or workflow edit.

Protected paths: CLI/package metadata. User's explicit ongoing upgrade and merge
request applies after source, installed wheel and final-head CI pass. Rollback:
revert the PR and pin a2; no state/config migration. Existing logs remain readable.
