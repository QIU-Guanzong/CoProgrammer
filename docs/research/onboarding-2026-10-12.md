# Onboarding and discoverability choices — 2026-10-12

- [GitHub's README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)
  centers purpose, usefulness, getting started and help. The revised README leads
  with a two-window problem and a checked offline demo. Full workflows move to
  linked guides; the English and Chinese pages carry the same capabilities and
  limitations.
- [gstack](https://github.com/garrytan/gstack) makes a development workflow
  tangible through named roles and a short first-use sequence. Here the entry
  points are `demo`, `start` and `status`; they describe actual local operations
  instead of promising an autonomous team or borrowing another project's scale.
- [Beads](https://github.com/gastownhall/beads) presents persistent agent work
  tracking. CoProgrammer's distinction is scoped ownership, path coordination,
  durable message receipts and inspectable integration artifacts through CLI/MCP.
- [Gas Town](https://github.com/gastownhall/gastown) describes a workspace manager
  and orchestration system with persistent work tracking. CoProgrammer continues
  to coordinate already-running clients; it does not add a terminal launcher,
  daemon, shared cloud queue or new transport in this release.

These are product choices inferred from the primary project documentation,
not comparative benchmarks. The display positioning is **CoProgrammer —
Teamwork for coding agents**. Existing package, repository and plugin identifiers
remain consistent with their released installation paths.

Discoverability changes: a concrete GitHub description, relevant topic labels,
shorter bilingual entry pages, an actual terminal excerpt, clear contribution
routes and a reproducible walkthrough. Their effect on stars has not been
measured. No testimonials, usage counts, performance claims or unsolicited
outreach are added.
